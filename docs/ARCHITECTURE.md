# Архитектура

Кандидат для MVP — Python, PostgreSQL, отдельный worker, FastAPI и простой кабинет после пилота. Coolify запускает отдельный Compose-проект. На этапе исследования достаточно локального прогона и таблицы результатов. PostgreSQL хранит очередь и результаты, поэтому отдельный брокер для пилота не нужен.

Планировщик → очередь → адаптер HTTP или Chromium → проверка снимка → PostgreSQL → кабинет и, позднее, правила dry-run. Адаптер возвращает идентификатор карточки, источник и версию, наблюдаемый регион и доказательство, доступность и два поля цены с отдельным состоянием каждого. Проверка бизнес-смысла едина для всех адаптеров. Seller API подключается отдельным клиентом и пишет собственные наблюдения с другим типом цены.

Назначить каждой карточке устойчивое смещение внутри 180 минут. Начать с одного активного задания. Использовать уникальность карточка + регион + слот, аренду задания с истечением и условное завершение по токену аренды. Атомарно фиксировать итог и снимок; сохранять ошибки попыток отдельно. После простоя пропускать истёкшие слоты с учётом их в метрике. Ограничить повторы временных сетевых сбоев; при блокировке или CAPTCHA остановить сбор с уведомлением.

При 1000 карточках средний интервал между стартами около 10,8 с. До расширения измерить полный цикл, p95 длительности, накопление очереди и пиковую память. Увеличивать объём ступенями при соблюдении лимитов площадки и ресурсов. Chromium — отдельный worker с лимитами, если выигрыш подтверждён.
