# Дорожная карта

| Фаза | Работы | Условие готовности |
|---|---|---|
| 0. Документация | Согласовать правила и план измерений | Десять документов просмотрены владельцем; подтверждён доступ к целевому репозиторию перед публикацией |
| 1. Исследование | A/B HTTP и Chromium, статический аудит проекта C, ручной эталон | Протокол с версиями и результатами каждого метода; выбран источник либо оформлено решение остановиться |
| 2. Минимальный сбор | Адаптер, валидация, история, четыре карточки; тест пропуска цены, неверного города и перезапуска | Выполнен входной критерий пилота; восстановление очереди без дублей; ошибки различимы |
| 3. Пилот | До 20 конкурентов, 14 дней, ручная сверка и контроль Repairkit | Отчёт по всем метрикам, решение владельца о дальнейшем использовании источника |
| 4. Кабинет | Список, связи, история, ошибки, ручная проверка и аудит настроек | Владелец может от исхода проверки перейти к доказательству и различить типы цен и их свежесть |
| 5. Seller API | Read-only сверка идентификаторов и цен; симуляция ответов записи и восстановления после неопределённого исхода | Контракт чтения подтверждён, результаты сопоставлены с кабинетом, сценарии записи проходят на заглушке; живой тест требует отдельного разрешения |
| 6. Репрайсер | Правила, МРЦ, dry-run, пауза, аудит, проверка применения | Сценарии ниже МРЦ, отсутствующей МРЦ, просрочки, массового сбоя, дубля и таймаута проверены. Автоматический режим только после отдельных испытаний и явного разрешения |
| 7. Масштаб | Нагрузочные прогоны на записанных примерах, ступени 100 → 1000 при достаточной ёмкости и доступе | Очередь укладывается в 180 минут, бюджет ресурсов и метрики качества соблюдены на каждой ступени |
