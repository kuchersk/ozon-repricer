# Исследование источников цен

Статический обзор на 17.11.2026. Реальные карточки и Seller API в авторизованной сессии не проверялись. Доступ к целевому репозиторию не подтверждён через публичный GitHub и API в доступном веб-инструменте; причины могут включать приватность или ограничения инструмента.

| Метод | Что проверить | Ограничение |
|---|---|---|
| A. HTTP | Маркированные обычная и карточная цены из доступных структурированных данных, однозначная связь с ID, продавцом и Москвой | HTML может содержать неполные данные, старую цену или значения другого варианта |
| B. Playwright | Цена и её подпись в видимом блоке, подтверждение Москвы через UI, повторяемость в чистом контексте | Выше стоимость CPU/RAM, возможны недоступность и изменения UI |
| C. parser_ozon | Проверить идеи выбора блока цены и сравнить с независимым адаптером | Демонстрация Telegram/CSV, пригодность для двух типизированных цен и Москвы не подтверждена |

В публичной ветке main видны .env, Dockerfile, Python-бот и requirements.txt; в дереве корня нет LICENSE. До подтверждения прав код не заимствовать. Статья описывает вывод одной цены, поиск блока webPrice, старые закреплённые версии Playwright 1.40.0, aiohttp 3.9.1, urllib3 2.1.0 и образ с Python 3.9. Также описаны отключение песочницы, игнорирование TLS-ошибок и маскировка автоматизации. Считать пример источником гипотез. Актуальность версии на текущем Chromium и наличие уязвимостей по полному дереву зависимостей остаются открытыми до закрепления SHA и аудита. [Статья Amvera](https://habr.com/ru/companies/amvera/articles/960280/) · [Исходники и файлы проекта](https://github.com/aglihowstan/parser_ozon)

Протокол. Зафиксировать версии, окружение, время и профиль покупателя. Сначала вручную записать регион, продавца, ID, вариант, наличие, подписи и суммы. Для A и B сравнить на тех же карточках и в близком временном окне. Повторить с чистой сессией и другим регионом в качестве отрицательного контроля. Сохранить обезличенные примеры пропуска карточной цены, недоступности, изменённой разметки и блокировки. Замерить длительность, объём данных, ошибки и peak RSS на задачу. Предпочтение HTTP при равной точности и подтверждаемом регионе. Если оба способа не проходят критерии, зафиксировать причину, использовать ручной мониторинг или искать разрешённый источник с обеими ценами.

## Seller API

- Список товаров — кандидат POST /v3/product/list, точный актуальный контракт и пагинацию перепроверить в документации кабинета. Детали — POST /v3/product/info/list. Цены и данные об акциях — POST /v5/product/info/prices. Версии двух последних подтверждены публикациями Ozon. [Версии методов](https://dev.ozon.ru/news/497-Novye-metody-dlia-raboty-s-tovarami-tsenami-i-kontentom-Seller-API/) · [Цены с учётом акций](https://dev.ozon.ru/news/787-Vazhnye-izmeneniia-v-metodakh-otchetov-Seller-API/)
- Изменение — POST /v1/product/import/prices. Ozon подтверждает метод и наличие валидации. До интеграции проверить поэлементный результат, ограничения и права ключа. Для подтверждения фактического применения запланировано повторное чтение /v5/product/info/prices с ограниченным окном ожидания. Отдельный endpoint статуса импорта цен не подтверждён. Не привязывать /v1/product/import/info к ценам без официального контракта на task_id именно для этого вызова. [FAQ Ozon](https://dev.ozon.ru/start/257-Seller-API-FAQ-spravochnik-oshibok-i-sposobov-ikh-resheniia) · [Документация Seller API](https://docs.ozon.ru/api/seller/)
- Сверить собственную карточку с ответами Seller API в московском покупательском профиле. Отдельно записать цену продавца, промо-поля, обычную витринную и цену с Картой. Проверить задержку обновления, правила акций и возможные расхождения из-за субсидий площадки. МРЦ относится к передаваемой цене продавца.

## Открытые риски и эксперименты

- Доступ с IP Selectel и условия площадки. После разрешения провести ограниченный проверочный прогон на VPS. Устойчивый запрет означает остановку этого источника.
- Изменение региона в сессии и персонализация. Сравнить чистую и повторную сессии, проверить отображаемый ПВЗ и воспроизводимость без аккаунта. Согласовать контрольный московский ПВЗ.
- Смена варианта и продавца, исчезновение одной цены, редизайн. Проверить разметку на сохранённых примерах и ручной выборке. Любая неоднозначность должна давать проверяемую ошибку.
- Ёмкость VPS. Сопоставить CPU, память, очередь и задержку Repairkit с базовым профилем. Уточнить пороги перед запуском.
- Seller API. Уточнить пагинацию, поля акций, лимиты, частичный отказ, задержку и наличие отдельного статуса обновления цен. На заглушке проверить отказ, таймаут и внешнее изменение цены между чтениями.
- Бизнес-параметры. Владелец утверждает допустимый тип ценового сигнала, окно свежести, лимиты изменений, МРЦ и правила действий при неполной группе до автоматизации.
