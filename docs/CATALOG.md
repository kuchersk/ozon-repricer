# Каталог товаров и ручное редактирование цены

Главная страница показывает каталог собственных товаров. Панель М3 доступна по /m3. Старые замеры, правила и журналы сохраняются. Расширение Chrome продолжает собирать М3. Сбор витрины остальных SKU — следующий этап.

## Первый запуск

1. Разверните обновлённую main в существующем приложении. Постоянный том /data остаётся подключён.
2. На главной странице нажмите «Импорт каталога JSON» и загрузите подготовленный файл ozon-catalog-270.json. В исходной выгрузке две дополнительные позиции имеют SKU=0 и вынесены в отдельный файл до присвоения SKU. Файл с данными кабинета передаётся только вашему серверу через защищённую панель и хранится в /data/catalog.local.json. Он не включён в Git. Повторный импорт добавляет новые товары, существующие настройки сохраняются. При конфликте SKU, Product ID или артикула импорт целиком отклоняется.
3. Нажмите «Обновить цены из Ozon». Сервер последовательно читает по 100 товаров за запрос, сверяя Product ID, offer_id и RUB. Предельная цена подписана отдельно от ориентира серой цены.
4. Для ручной записи добавьте в Production / Runtime OZON_CATALOG_MANUAL_WRITE=1 и OZON_OBSERVER_WRITE_KEY с правом изменения цен. Переразверните приложение. Одноразовый автопилот М3 должен быть выключен (OZON_ENABLE_M3_AUTO_PILOT=0), так как эти два режима используют одну цену продавца.
5. В строке товара нажмите «Редактировать». Сохраните минимальную предельную цену. Укажите новую предельную сумму и нажмите «Проверить изменение». Предельная сумма задаётся оператором, ориентир серой цены не преобразуется в неё автоматически.
6. Проверьте товар и обе суммы. Нажмите «Подтвердить запись» в пределах двух минут. Сервис повторно прочитает исходные значения, отправит одинаковую сумму в price и min_price и перечитает оба поля. Частично подтверждённая запись блокирует следующие изменения этого SKU. «Проверить результат» выполняет только чтение.
7. После успешной записи проверьте серую цену на витрине отдельным замером. Запись предельной цены не гарантирует фиксированную серую цену.

В каталоге загружены названия и статусы на дату исходной выгрузки. Поиск работает по названию, SKU и артикулу продавца. Прокрутка списка сохраняет заголовки столбцов. Ориентиры прайса требуют подтверждения комплектации. Пустое значение обозначает отсутствие сопоставления. Минимальная предельная цена задаётся отдельно по каждому товару.

## Хранение и проверка

Каталог, настройки, снимки Seller API и журнал ручных операций сохраняются атомарной заменой файла catalog.local.json в /data. Рекомендуется одна реплика приложения. Перед изменениями включите резервное копирование тома. Для резервной копии остановите только это приложение и скопируйте /data в отдельное место хранения с ограниченным доступом. Восстановление проверяется на отдельном томе. Копия на этом же VPS не защищает от потери сервера.

Повторный запрос той же операции возвращает её статус. Если ответ потерялся, проверьте журнал и используйте чтение результата. Не удаляйте незавершённые операции ради повтора. При изменении исходной цены в Ozon или минимума подтверждение отклоняется.

Предыдущая одноразовая запись и автопилот М3 сохраняют свои ограничения. Ручная запись из каталога учитывается в истории М3 для пауз и дневных лимитов dry-run. Каталог обеспечивает ручное редактирование по каждому SKU. Пауза и дневной лимит автоматического репрайсера относятся к автоматическим расчётам, оператор вручную подтверждает каждую запись каталога.

## Проверка релиза

До включения реального ключа проверяются импорт более 200 строк, три последовательных запроса чтения, несопоставленные товары, изменение настроек, защита минимума, точный Product ID/артикул, запись двух полей, повторный клик, незавершённая запись и сохранение после перезапуска. Проверки используют заглушку Ozon, цены рабочего кабинета не затрагиваются.

Запуск: `node tests/catalog-integration.cjs`. Не требует внешних библиотек или настоящих ключей. Проверка использует временный каталог и порт 18766.
